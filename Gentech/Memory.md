## How We Work

### Build Pipeline
1. **PLAN** — Check what exists, break into tasks, define success criteria
2. **BUILD** (DeepSeek V4 Flash) — TDD: write failing test first, then minimal code
3. **AUDIT** (Kimi K2.7) — Security scan, plan compliance, persistence verification
4. **FINISH** — Full test suite, commit, push, verify deployment
5. **VERIFY** — "Done" means verified, not declared. Read-back every file.

### Communication
- **HQ** — Coordination, decisions, blockers, status
- **Labs** — Code, SDKs, smart contracts, technical dev
- **Strategies** — Finance, DeFi, portfolio, yield, market analysis
- **Entertainment** — Content, social media, hackathon submissions
- Blockers surface **immediately** — never in status reports

### Key Rules
- Build first, talk later — ship products, not plans
- No silent assumptions — state what you're assuming or ask
- No drive-by improvements — touch only what you must
- No declaring done without proof — verify persistence
- Jordan is the boss — when he asks, you do
